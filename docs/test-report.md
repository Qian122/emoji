## 5 人工端到端验收

### 5.1 三角色流程

1. 管理员创建课程、课堂并安排学生。
2. 学生重新登录，确认能看到新课堂并提交情绪。
3. 教师打开该课堂看板，确认统计和最新动态自动刷新。
4. 教师尝试访问不属于自己的课堂，应被拒绝。
5. 管理员按课程、班级和时间筛选统计，并导出同一范围 CSV。

### 5.2 AI 流程

1. 使用 Python 3.11.9 启动后端和完整 AI 服务，健康检查返回 `visionAvailable=true`，检测器顺序为 OpenCV、MTCNN。
2. 调用 `/simulate` 验证匿名 AI 记录、置信度字段、后端入库和看板事件链路；低于阈值的模拟结果返回 `LOW_CONFIDENCE` 且不入库。
3. 摄像头 0 可被 OpenCV 打开并读取 640×480 内存帧；`/camera/start` 与 `/camera/stop` 可切换运行状态并释放设备。
4. 使用真实人脸帧调用 `/analyze-frame`，曾得到 `neutral → CALM`、置信度 0.9828 的有效结果并写入 SQLite；另一次 Web 代理测试得到 `HAPPY`、置信度 0.9015 的结果并成功入库。
5. OpenCV 漏检对照中，MTCNN 对同一组 5 帧均能检测到人脸，证明双检测器兜底路径可用。启用画面放大后，代理响应可返回 `detectorBackend=mtcnn`。
6. 最新一次连续 5 帧复测均返回未检测到人脸。该结果可能由镜头前无人、隐私挡板、姿态、距离或环境光造成，因此不作为识别成功证据，也不据此计算模型准确率。
7. 自动化测试已覆盖无人脸、检测器兜底、连续 3 帧融合、候选差值、帧间一致性和严重低质量画面过滤。
8. Web 摄像头页面支持镜像预览、单帧检测、连续检测、课堂选择、前三类概率、图像质量、过滤原因、计数反馈和停止释放。
9. 检查项目目录与 `data/`，未发现由程序生成的原始人脸图像或视频文件。当前健康状态为 `cameraRunning=false`。

## 9 缺陷与处理记录

| 编号 | 现象 | 影响 | 处理结果 |
|---|---|---|---|
| D01 | 初版教师数据查询需强化课堂归属边界 | 教师可能访问非本人课堂 | 后端统一追加教师条件并增加 T05/T14 |
| D02 | 排课名单只保存增量时可能残留旧学生 | 名单与管理员操作不一致 | 改为事务内完整替换并支持清空 |
| D03 | CSV 危险前缀可能被 Excel 当作公式 | 导出安全风险 | 增加前缀转义并增加 T09/T12 |
| D04 | 缺少 OpenCV 时 AI 服务无法演示 | 阻塞非视觉功能验证 | 将视觉依赖延迟加载，保留 health/simulate |
| D05 | 管理员注册保护缺少独立验证 | 安全证据不足 | 增加注册码校验测试 T13 |
| D06 | TensorFlow 2.21 下 DeepFace 缺少 `tf-keras` | DeepFace 无法导入 | 将 `tf-keras==2.21.0` 加入完整依赖并验证导入 |
| D07 | `enforce_detection=false` 会将无人脸背景当作情绪 | 可能写入错误 AI 记录 | 开启强制人脸检测，无人脸时不输出情绪 |
| D08 | 无人脸属于正常采样状态但会反复打印异常 | 课堂运行日志噪声过多 | 无人脸时返回空结果，并增加 A05 回归测试 |
| D09 | 摄像头隐私挡板或系统权限关闭时只返回无效画面 | 无法检测真人面部 | Web 页面显示实时预览和状态，便于测试者先确认画面 |
| D10 | 原有 Web 页面无法看到摄像头取景 | 测试人员难以确认面部位置、光线和隐私开关状态 | 新增 AI 摄像头页面、实时预览、单帧/连续检测、状态和计数反馈 |
| D11 | OpenCV 检测器在真实 640×480 画面中偶发漏检 | 画面中有人但返回“未检测到人脸” | 改为 OpenCV 快速检测，失败后放大画面并使用 MTCNN；人脸区域扩展 15%，Web 优先请求 1280×720，单次操作最多采集 6 帧以获得 3 个有效人脸帧 |
| D12 | 单帧 DeepFace 结果在愤怒、悲伤、平静之间跳变 | 课堂记录容易受瞬时表情和模型波动影响 | 保留全部类别概率并融合连续 3 帧，增加类别独立阈值、候选差值、帧间一致性和画面质量过滤 |

自动化测试没有遗留失败项，已发现缺陷均完成修复并纳入回归测试。
