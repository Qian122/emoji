# 测试用例说明书

## 1 测试目标

验证系统四类参与者的核心业务、权限边界、数据正确性、实时通信、安全措施、AI 集成、部署和文档完整性。测试遵循“正常流程、异常输入、越权边界、外部依赖降级”四类场景。

## 2 测试数据

| 角色 | 用户名 | 初始密码 | 说明 |
|---|---|---|---|
| 学生 | student | Student123! | 已安排到演示课堂 |
| 教师 | teacher | Teacher123! | 演示课程教师 |
| 管理员 | admin | Admin123! | 具有全局管理权限 |

自动化测试使用内存数据库，每个测试重新生成数据。人工验收使用本地 SQLite，测试结束后可删除测试账号或恢复数据库备份。

## 3 功能与安全测试用例

### TC-01 学生注册

- 前置条件：用户名和邮箱未被占用。
- 步骤：打开注册页；输入合法学生信息；提交。
- 预期：返回注册成功，角色为 STUDENT，可使用新账号登录。
- 异常分支：弱密码返回 400；重复用户名或邮箱返回 409。
- 自动化证据：T02。

### TC-02 管理员安全注册

- 前置条件：已配置 `ADMIN_REGISTRATION_CODE`。
- 步骤：分别使用错误和正确注册码注册管理员。
- 预期：错误注册码返回 403；正确注册码返回 201，账号角色为 ADMIN。
- 自动化证据：T13。

### TC-03 登录与 JWT

- 前置条件：账号状态为 ACTIVE。
- 步骤：使用正确密码登录；携带 JWT 查询当前用户；去掉 JWT 再查询。
- 预期：正确凭据返回 JWT；带 JWT 查询成功；无 JWT 返回 401。
- 自动化证据：T01、T03。

### TC-04 修改密码

- 前置条件：用户已登录。
- 步骤：输入当前密码和新密码；退出；分别使用旧密码和新密码登录。
- 预期：修改成功；旧密码失败；新密码成功。
- 自动化证据：T02。

### TC-05 账号停用

- 前置条件：学生已获得 JWT，管理员已登录。
- 步骤：管理员停用学生；学生继续使用旧 JWT 请求个人接口。
- 预期：旧 JWT 立即返回 401；停用账号无法重新登录。
- 自动化证据：T10。

### TC-06 管理员自停用保护

- 前置条件：管理员已登录。
- 步骤：尝试将当前管理员状态改为 DISABLED。
- 预期：返回 400，不修改账号状态。
- 验证方式：人工接口测试和代码审查。

### TC-07 创建课程

- 前置条件：管理员已登录，存在有效教师。
- 步骤：选择教师并创建课程；再尝试使用学生 ID 创建课程。
- 预期：有效教师创建成功；学生 ID 被拒绝。
- 自动化证据：T04。

### TC-08 创建课堂会话

- 前置条件：课程已存在。
- 步骤：输入班级、教室、起止时间并保存；再提交结束早于开始的时间。
- 预期：合法课堂创建成功；错误时间范围返回 400。
- 自动化证据：T04、T06。

### TC-09 安排课堂名单

- 前置条件：课堂及学生存在。
- 步骤：保存多个学生；重新打开检查回显；移除一个学生；提交空列表。
- 预期：名单始终与最后一次提交完全一致，空列表可以清空。
- 自动化证据：T04。

### TC-10 排课名单角色校验

- 前置条件：存在学生和教师。
- 步骤：将教师 ID 放入课堂名单。
- 预期：返回 400，不写入任何无效关系。
- 自动化证据：T04。

### TC-11 学生手动提交 emoji

- 前置条件：学生已排课并登录。
- 步骤：选择课堂；依次提交六种表情。
- 预期：每次返回成功；历史记录来源为 MANUAL，包含课堂和时间。
- 自动化证据：T01。

### TC-12 学生未排课越权

- 前置条件：另建一个未安排当前学生的课堂。
- 步骤：手工构造请求向该课堂提交 emoji。
- 预期：返回 403，数据库无新增记录。
- 自动化证据：T01、T04 的权限链路。

### TC-13 学生个人历史隔离

- 前置条件：多个学生均有记录。
- 步骤：学生查询历史并检查每条 `userId`。
- 预期：只返回当前学生记录。
- 自动化证据：T01。

### TC-14 教师课堂历史隔离

- 前置条件：至少两名教师及各自课堂均有记录。
- 步骤：教师查询全部历史并尝试指定其他教师课堂。
- 预期：只返回本人课堂；指定其他课堂返回 403；记录包含学生用户名。
- 自动化证据：T05、T14。

### TC-15 实时看板

- 前置条件：教师看板和学生页面同时打开同一课堂。
- 步骤：教师加入课堂房间；学生提交新表情。
- 预期：教师收到 `emoji:new`，看板自动刷新，样本数和趋势变化。
- 自动化证据：T07。

### TC-16 Socket.IO 房间隔离

- 前置条件：存在其他教师课堂。
- 步骤：教师尝试加入非本人课堂房间。
- 预期：服务端拒绝，不接收该课堂事件。
- 自动化证据：T05、T07 及实时模块代码审查。

### TC-17 多维统计

- 前置条件：不同课程、班级和时间均有记录。
- 步骤：分别选择课程、班级、时间范围及组合条件。
- 预期：分布、课堂样本和趋势同步变化，数据只属于筛选范围。
- 自动化证据：T06。

### TC-18 CSV 导出

- 前置条件：管理员已登录并设置统计筛选。
- 步骤：导出 CSV；使用 Excel 打开；核对筛选条件和中文。
- 预期：文件带 UTF-8 BOM，中文正常，内容与筛选一致。
- 自动化证据：T09。

### TC-19 CSV 公式注入防护

- 前置条件：设备标识包含 `= + - @` 等危险前缀。
- 步骤：导出 CSV 并查看对应单元格原始值。
- 预期：危险值前增加单引号，不被 Excel 当作公式执行。
- 自动化证据：T09、T12。

### TC-20 AI 令牌

- 前置条件：后端运行。
- 步骤：分别使用错误和正确 AI 令牌提交相同结果。
- 预期：错误令牌返回 401；正确令牌继续执行阈值校验。
- 自动化证据：T08。

### TC-21 AI 置信度过滤

- 前置条件：阈值设为 0.65。
- 步骤：提交 0.60 和 0.90 两条结果。
- 预期：0.60 不入库；0.90 以 AI 来源入库。
- 自动化证据：A02、A03、T08。

### TC-22 AI 匿名与隐私

- 前置条件：AI 服务运行。
- 步骤：执行模拟或摄像头推理；检查数据库和项目目录。
- 预期：AI 记录 `user_id=NULL`；不存在原始帧或视频文件。
- 自动化证据：T08；人工检查 `data/`。

### TC-23 缺失视觉依赖的降级

- 前置条件：未安装 OpenCV/DeepFace。
- 步骤：启动 AI 服务；访问 `/health`、`/simulate` 和摄像头接口。
- 预期：前两项正常；摄像头接口明确返回 503。
- 自动化证据：A01、A04。

### TC-24 真实摄像头推理

- 前置条件：Python 3.11、完整依赖、摄像头和模型均可用。
- 步骤：启动课堂；调用摄像头启动接口；在镜头前呈现不同表情；停止摄像头。
- 预期：高置信度结果写入数据库并更新看板；停止后设备释放；不保存原始视频。
- 验收重点：高置信度结果写入数据库、看板刷新、摄像头释放且原始视频不落盘。

### TC-25 连续帧与歧义过滤

- 前置条件：AI 服务和摄像头正常。
- 步骤：保持同一表情至少 3 帧；再测试愤怒与悲伤特征不明显、光线极暗和明显晃动的场景。
- 预期：稳定结果经 3 帧融合后输出；第一、第二候选接近时返回 `AMBIGUOUS`；帧间不一致时返回 `UNSTABLE`；严重低质量画面返回 `LOW_IMAGE_QUALITY`，均不入库。
- 自动化证据：A07-A09。

### TC-26 构建与部署

- 前置条件：Node.js 24、Python 3.11；Docker 测试需 Docker Desktop。
- 步骤：执行静态检查、两端测试、本机启动；再执行 Compose 构建和启动。
- 预期：所有命令退出码为 0，健康检查成功，重启后数据仍存在。
- 自动化证据：CI 配置；Docker 部分需现场执行。

## 5 回归测试要求

每次修改认证、权限、统计 SQL、实时模块或 AI 映射后，至少执行：

```powershell
npm run check
npm test
npm run test:ai
```

涉及部署文件时增加 `docker compose config`；涉及数据库结构时必须备份旧数据库并验证迁移；涉及摄像头时必须重新执行 TC-24。

## 6 通过准则

- 必做功能测试不得存在失败项。
- 安全和越权测试不得降级为“已知问题”。
- 自动化测试应达到 Node 16/16、AI 9/9。
- Docker、Git 历史和演示流畅度必须在最终提交设备人工确认。
- 一旦发现阻塞级问题，应停止提交，修复后重新执行完整回归。
