# 完整人工测试操作手册

## 1 测试目标

本手册用于现场验收表情符号课堂情绪检查器。测试内容覆盖学生、教师、管理员、AI 推理、摄像头、实时通信、安全、统计、导出、部署和提交材料。

## 2 测试环境准备

### 2.1 启动后端

在项目目录执行：

```powershell
npm install
npm start
```

打开：

```text
http://localhost:3000
```

预期结果：登录页面正常显示，访问 `http://localhost:3000/api/health` 返回 `status=UP`。

### 2.2 启动 AI 服务

首次使用完整视觉功能时执行：

```powershell
py -3.11 -m venv .venv-ai
.\.venv-ai\Scripts\python.exe -m pip install -r .\ai-service\requirements.txt
.\.venv-ai\Scripts\python.exe -m uvicorn main:app --app-dir ai-service --host 127.0.0.1 --port 8000
```

预期结果：访问 `http://127.0.0.1:8000/health`，返回：

- `status` 为 `UP`；
- `visionAvailable` 为 `true`；
- `cameraRunning` 初始为 `false`。

### 2.3 演示账号

| 角色 | 用户名 | 初始密码 |
|---|---|---|
| 学生 | `student` | `Student123!` |
| 教师 | `teacher` | `Teacher123!` |
| 管理员 | `admin` | `Admin123!` |

管理员注册还需要 `.env` 中的 `ADMIN_REGISTRATION_CODE`。测试时只复制注册码到注册表单，不在截图、报告或录屏中展示 `.env`。

## 3 注册与登录测试

### 3.1 学生注册

1. 打开登录页，点击“注册”。
2. 用户名填写未使用的名称，例如 `student_test_01`。
3. 邮箱填写未使用的邮箱，例如 `student_test_01@example.edu`。
4. 密码填写 `StudentTest123!`。
5. 角色选择“学生”。
6. 点击“创建账号”。

预期结果：注册成功并自动进入学生页面，左下角角色显示“学生”。

### 3.2 教师注册

1. 退出当前账号，点击“注册”。
2. 填写新的用户名和邮箱。
3. 使用至少 8 位并包含大小写字母和数字的密码，例如 `TeacherTest123!`。
4. 角色选择“教师”。
5. 点击“创建账号”。

预期结果：注册成功，教师只能看到本人被分配的课程、课堂和统计数据。

### 3.3 管理员注册

1. 退出当前账号，点击“注册”。
2. 填写新的用户名、邮箱和强密码。
3. 角色选择“管理员”。
4. 页面出现“管理员注册码”输入框。
5. 先填写错误注册码并提交。
6. 再填写 `.env` 中真实的 `ADMIN_REGISTRATION_CODE` 并提交。

预期结果：

- 错误注册码返回“管理员注册码无效”；
- 正确注册码注册成功；
- 新管理员可查看用户、课程、课堂、排课、全部情绪数据、统计和导出页面。

### 3.4 登录异常测试

1. 使用正确用户名和错误密码登录。
2. 不填写用户名或密码直接提交。
3. 使用已被管理员停用的账号登录。

预期结果：分别提示用户名或密码错误、请输入完整信息、账号已停用，不进入系统。

## 4 修改密码测试

学生、教师和管理员分别执行一次：

1. 登录账号。
2. 进入“账号设置”。
3. 当前密码填写错误值，新密码填写 `ChangedTest123!` 并提交。
4. 当前密码填写正确值，新密码填写弱密码 `12345678` 并提交。
5. 当前密码填写正确值，新密码填写符合要求的新密码并提交。
6. 退出登录。
7. 分别尝试旧密码和新密码登录。

预期结果：

- 当前密码错误时拒绝修改；
- 弱密码被拒绝；
- 合规密码修改成功；
- 旧密码失效，新密码登录成功。

测试完成后可将演示账号密码改回原始值，避免影响后续演示。

## 5 管理员功能测试

### 5.1 查看和停用用户

1. 使用管理员登录。
2. 打开“用户管理”。
3. 检查学生、教师、管理员的用户名、邮箱、角色、状态和注册时间。
4. 让测试学生保持登录状态。
5. 管理员点击该学生的“停用”。
6. 学生刷新页面或打开任意功能。
7. 管理员再次点击“启用”。

预期结果：学生被停用后，已签发的登录状态立即失效；重新启用后可再次登录。管理员不能停用自己当前正在使用的账号。

### 5.2 创建课程

1. 打开“课程与排课”。
2. 在“创建课程”中填写唯一课程名称，例如“人工验收课程”。
3. 选择一个有效教师。
4. 点击“创建课程”。

预期结果：页面提示课程创建成功，新课程出现在课堂创建区域的课程下拉框中。

### 5.3 创建课堂会话

1. 选择刚创建的课程。
2. 设置开始时间和结束时间，结束时间必须晚于开始时间。
3. 填写班级和教室。
4. 提交创建。
5. 再测试一次结束时间早于开始时间的情况。

预期结果：正常时间可创建课堂；错误时间被拒绝。

### 5.4 安排学生名单

1. 在“安排课堂用户”中选择课堂。
2. 按住 `Ctrl` 多选学生。
3. 点击“保存安排”。
4. 切换到其他课堂，再切回原课堂。
5. 取消所有学生选择并保存。

预期结果：名单能够正确回显；保存操作完整替换名单；空名单可正常保存。

### 5.5 情绪数据与统计

1. 打开“情绪数据”，检查学生手动记录和 AI 记录。
2. 检查记录的情绪、课堂、来源、置信度和时间。
3. 打开“统计与导出”。
4. 分别按课程、班级、开始时间、结束时间筛选。
5. 组合多个筛选条件。
6. 设置开始时间晚于结束时间。

预期结果：统计卡片、情绪分布、课堂样本量和趋势图随筛选变化；错误时间范围被拒绝。

### 5.6 CSV 导出

1. 在“统计与导出”中设置筛选条件。
2. 点击“导出筛选结果”。
3. 使用 Excel 或表格软件打开 CSV。

预期结果：

- 文件使用 UTF-8，中文显示正常；
- 数据范围与页面筛选一致；
- 包含用户名、课程、班级、情绪、来源、置信度、设备标识和时间；
- 以 `= + - @` 开头的危险字段不会被当作公式执行。

## 6 学生功能测试

2. 学生重新登录。
3. 打开“情绪打卡”。

预期结果：学生只能看到自己被安排的课堂，不能看到其他课堂。

### 6.2 提交六类 emoji

依次点击：开心、平静、困惑、难过、生气、惊讶。

预期结果：每次提交均提示记录成功；本课堂情绪分布和最近反馈同步变化。

### 6.3 查看个人历史

1. 打开“我的历史”。
2. 选择全部课堂和指定课堂查看。

预期结果：只显示当前学生自己的记录，不显示其他学生数据。

## 7 教师功能测试

### 7.1 课堂数据隔离

1. 管理员创建两门课程，分别指定不同教师。
2. 两名教师分别登录。
3. 检查教学看板、课堂记录和统计分析。

预期结果：每名教师只能查看本人所授课堂，不能查看另一教师的课堂数据。

### 7.2 实时看板

1. 教师打开“教学看板”并选择课堂。
2. 学生在另一个浏览器窗口向同一课堂提交 emoji。
3. 连续提交不同情绪。

预期结果：教师页面无需手动刷新即可更新样本量、主导情绪、需关注反馈、最新动态和趋势。

### 7.3 教师历史与统计

1. 打开“课堂记录”。
2. 选择指定课堂。
3. 打开“统计分析”，组合课程、班级和时间筛选。

预期结果：教师可看到课堂中的学生名称和记录，但数据始终限制在本人课程范围内；教师页面没有 CSV 导出按钮。

## 8 Web 端 AI 摄像头测试

### 8.1 打开实时预览

1. 确认 AI 服务已启动，`visionAvailable=true`。
2. 使用教师或管理员登录。
3. 打开“AI 摄像头”。
4. 点击“打开摄像头预览”。
5. 浏览器出现权限提示时选择“允许”。

预期结果：页面实时显示镜像摄像头画面，状态显示“预览中”。测试人员可以看到自己的面部位置和光照情况。

系统优先使用 OpenCV 快速检测；没有发现人脸时，会放大低分辨率画面并自动使用 MTCNN 再检测一次。浏览器优先请求 1280×720 画面，单次操作最多重试 3 个画面以寻找有效人脸；每个有效画面独立判断，不进行多帧概率融合。

如果画面为灰色锁图标，打开电脑的物理摄像头挡板或关闭联想摄像头隐私模式。

### 8.2 单帧检测

1. 在页面选择要写入的课堂。
2. 面部正对镜头。
3. 点击“检测当前画面”。
4. 分别测试无人画面、正常表情和明显微笑。

预期结果：

- 无人脸时显示“未检测到人脸”，不写入数据库；
- 检测到人脸但置信度低于阈值时显示“已过滤”；
- 高于阈值时显示原始情绪、映射后的 emoji、置信度和“已入库”；
- 教师实时看板同步出现 AI 记录。

### 8.3 连续检测

1. 点击“开始连续检测”。
2. 保持面部入镜 20-30 秒，依次展示平静和微笑表情。
3. 观察“已检测、已入库、已过滤”计数。
4. 点击“停止并释放”。

预期结果：每约 3 秒采样一次；超过阈值的记录匿名写入数据库；停止后页面显示“摄像头已关闭并释放”，摄像头指示灯熄灭，其他应用能够使用摄像头。

### 8.4 页面离开与权限测试

1. 打开预览后切换到其他菜单。
2. 再次返回 AI 摄像头页面。
3. 在浏览器设置中拒绝摄像头权限后重新打开预览。
4. 使用学生账号尝试访问 AI 摄像头接口。

预期结果：离开页面立即释放摄像头；拒绝权限时页面显示明确提示；学生没有 AI 摄像头菜单，直接调用接口返回 403。

### 8.5 隐私检查

完成摄像头测试后检查：

```powershell
Get-ChildItem .\data -Recurse
```

预期结果：只存在数据库文件，不存在 `.jpg`、`.png`、`.mp4`、`.avi` 等原始人脸图片或视频。浏览器画面和上传帧只在内存中使用。

## 9 AI 接口测试

### 9.1 健康检查

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

预期结果：状态正常、视觉依赖可用、阈值与 `.env` 一致。

### 9.2 模拟 AI 结果

```powershell
$body = @{ sessionId = 1; emojiType = 'HAPPY'; confidence = 0.90; deviceId = 'manual-ai-test' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/simulate -ContentType application/json -Body $body
```

预期结果：记录写入后端，来源为 AI，用户为匿名，置信度为 0.90。

### 9.3 低置信度过滤

将上一步的 `confidence` 改为 `0.10`。

预期结果：返回 `LOW_CONFIDENCE`，数据库不新增记录。

### 9.4 AI 服务不可用

1. 停止 8000 端口 AI 服务。
2. 打开 Web 端“AI 摄像头”。
3. 尝试检测画面。

预期结果：页面显示 AI 服务不可用，后端和其他业务功能仍正常工作。

## 10 安全与异常测试

| 测试项 | 操作 | 预期结果 |
|---|---|---|
| 未登录访问 | 清除登录状态后访问管理接口 | 返回 401 |
| 学生越权 | 学生访问用户管理或统计管理接口 | 返回 403 |
| 教师越权 | 教师访问其他教师课堂 | 返回 403 |
| 错误 AI 令牌 | 使用错误 `X-AI-Token` 提交 AI 结果 | 返回 401 |
| 弱密码 | 使用纯数字或缺少大小写字母的密码 | 返回 400 |
| 重复账号 | 使用已存在用户名或邮箱注册 | 返回 409 |
| 非法课堂编号 | 提交不存在或负数课堂编号 | 返回 400 或 404 |
| 超长设备标识 | 提交超过 100 字符的设备标识 | 返回 400 |
| 停用账号旧令牌 | 停用已登录账号后继续请求 | 返回 401 |
